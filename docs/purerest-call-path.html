System design — pure-service

purerest, and its two consumers

A Cats-Effect platform library, and the request path that exercises it.

Scala 3.9.0 Cats Effect 3.7.0 http4s 0.23.37 sbt multi-module

purerest is a small Cats-Effect-native library: an http4s client, OpenTelemetry tracing (otel4s), and trace-correlated structured logging (log4cats), each exposed as a plain value or combinator rather than an annotation. order-service and inventory-service are its two consumers — ordinary http4s servers that pull purerest in as an sbt module dependency, the same way they'd pull in any other library. The diagram below follows one request, POST /orders, from curl through both services and into purerest, and shows exactly which parts of the library each service's own Main.scala actually constructs.

purerest's current surface, in full: a client wrapper, tracing, and logging — no retry, circuit breaker, or metrics module exists in modules/purerest/src/main yet; both stores are in-memory, no persistence layer.
